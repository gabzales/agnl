PageSpeed Insights sebelumnya menunjukkan LCP 66 detik di mobile dan
total payload halaman ~14MB, hampir semuanya gambar. Penyebabnya:
tidak ada proses kompres/resize sama sekali saat upload -- file yang
diupload admin (produk/banner/avatar/QRIS) disimpan & disajikan apa
adanya, sebesar apapun aslinya.

Sekarang SETIAP upload gambar baru otomatis:
  - Di-resize maksimal 1600px sisi terpanjang
  - Dikonversi ke WebP kualitas 80 (jauh lebih kecil dari PNG/JPG
    mentah, kualitas visual hampir tidak beda)
  - GIF dikecualikan (dibiarkan apa adanya supaya animasi tidak hilang)

PENTING: ini cuma berlaku untuk gambar yang diupload SETELAH update
ini di-deploy. Untuk gambar produk/banner LAMA yang sudah kadung besar,
migrasikan lewat salah satu cara berikut (tidak perlu re-upload manual
satu-satu):

CARA PALING GAMPANG (lewat browser, tidak perlu .env / terminal / login
admin sama sekali -- pakai env Supabase yang sudah ada di Vercel):
  1. Set SETUP_SECRET di Vercel Environment Variables (string acak
     rahasia apa saja, cuma kamu yang tahu) -- redeploy setelah diisi.
  2. Buka: https://agha.nlstoreshop.my.id/admin/migrate-images?secret=ISI_SECRET_KAMU
     (ganti ISI_SECRET_KAMU dengan value dari langkah 1)
  3. Progress muncul live di halaman. Kalau ada tulisan "Sisa belum
     diproses" di akhir, refresh/buka lagi URL yang sama untuk lanjutkan
     (satu panggilan cuma proses maks 15 file dulu supaya tidak kena
     timeout Vercel -- aman diulang, file yang sudah selesai otomatis
     dilewati).
  4. Setelah selesai, HAPUS SETUP_SECRET dari Vercel Environment
     Variables -- endpoint ini otomatis nonaktif total (403) kalau
     SETUP_SECRET tidak di-set, jadi aman dari akses tak sah selama
     env itu kosong.

CARA ALTERNATIF (dari terminal lokal, kalau .env sudah terisi
SUPABASE_URL & SUPABASE_SERVICE_ROLE_KEY):
    node migrate-images-to-webp.js

Kedua cara memakai logic yang sama: mengambil semua gambar lama di
Supabase Storage, mengompresnya jadi WebP, memperbarui semua referensi
URL di products.json/users.json/settings.json, lalu menghapus file
lama. Aman dijalankan/diakses lebih dari sekali (file yang sudah .webp
otomatis dilewati).
